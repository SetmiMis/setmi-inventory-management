# FEATURE-003: Barcode generation, label printing, scanning

**Status:** IMPLEMENTED 2026-10-24 (owner approved the EAN-13 plan). Not yet tried on a real printer or scanner. Billing (P7) not built. Printer type and label size were not answered; label page offers presets (below) plus the owner can say the real size later.
Owner request: when an item is created the system should give it a barcode, the owner prints it, and scans it for billing.

## 0. What exists now (actual code)
- DB (migration 4, applied): sequence `item_barcode_seq`, `ean13_check_digit()`, `generate_item_barcode(item)` (needs `items.edit`, idempotent, audit-logged), column `item_barcodes.is_generated`. Tests `supabase/tests/004_barcode_generation.sql`: 13/13 pass.
- `src/lib/barcode/ean13.ts`: check digit, bar pattern (95 modules). Tests `tests/ean13.test.ts`.
- **Independent check:** the ZXing reader (a separate open-source barcode reader, installed in a throw-away folder only) decoded 2112 of 2112 rendered barcodes correctly (704 numbers: every first digit 0-9, 300 numbers shaped like ours, real EAN numbers; at 3 sizes).
- UI: new-item form has "Generate a SETMI barcode" (ticked by default); item page has a "Generate barcode" button, a "generated by SETMI" tag and a "Print labels" link; `/items/[id]/labels` prints labels (presets: thermal 50x25, 38x25, 60x40 mm; A4 sheets 65 or 24 labels; copies 1-200); the items search box is autofocused and jumps straight to the item when the text equals one barcode.
- Bar height is computed from the label size so bars stay at least about 0.26 mm wide (EAN-13 readable range).
- Known gaps: SVG placement inside the page was not scanned from a real print; only the same module string was decoded. Sequence numbers 1 and 2 were used up by DB tests, so the first real barcode is ...003 (harmless). Only EAN-13 barcodes can be printed; a manufacturer barcode in another format (EAN-8, Code 128) shows no Print link.

## 1. What the owner wants
1. Create item -> system generates a barcode for it.
2. Print barcode labels (stickers).
3. Scan a barcode to find the item, and use that scan in billing (billing module is P7).

## 2. Proposed design (AI proposal, needs owner "haan")
**Format: EAN-13**, 13 digits, built as `2` + 11-digit running number + check digit.
- Numbers starting with 2 belong to the range reserved for in-store/internal use, so they cannot clash with a real manufacturer barcode on someone else's product.
- EAN-13 is read by every ordinary USB scanner and billing software.
- The running number comes from a database sequence, so two users creating items at the same moment can never get the same barcode.
- The generated barcode is stored in `item_barcodes` like any other barcode (same uniqueness rule: one barcode, one item), marked `is_generated = true`. Items that already carry a manufacturer barcode keep it; a generated one is added only when asked.

**Where:** database function `generate_item_barcode(item_id)`: needs `items.edit`, returns the existing generated barcode if the item already has one (never creates a second by accident).

**Alternatives considered**
| Option | Verdict |
|---|---|
| Code 128 of the Internal_Item_Code | Rejected: the owner's codes are up to ~85 characters ("SETMI-" + full name); the bars would be far too wide for a sticker |
| Code 128 of a short generated number | Works, but EAN-13 is the retail standard and every shop scanner reads it with no setup |
| QR code | Rejected for billing: cheap USB scanners often do not read QR |

## 3. Printing
- Label page per item: `/items/[id]/labels` with a copies box and a size choice, printed from the browser (Ctrl+P). Bars are drawn as SVG on the server/client, no image files.
- Label shows: Selling Item Name (as on the bill), the barcode, the 13 digits.
- Needs from the owner: **which printer and label size?** (thermal label printer such as 50x25 mm, or A4 sticker sheet). Presets will be built for the answer.
- Later: print many items at once, from the item list.

## 4. Scanning
- A USB scanner works like a keyboard: it "types" the digits and presses Enter. The item search box (autofocused) will jump straight to the item when the text is exactly one barcode.
- Billing (P7) will use the same lookup: scan -> item -> bill line using `Selling_Item_Name`.
- Phone-camera scanning: possible later (browser BarcodeDetector support varies), not in the first version.

## 5. Accuracy and security
- The EAN-13 encoder is written in this project (no new package). It will be checked against an independent decoder (a library in a throw-away folder reads the generated SVG back) and unit tests (check digit, length 95 modules). A wrong table would print unreadable stickers, so this is verified before use.
- Barcode text is validated (digits only, correct check digit) before drawing.
- Printing a label needs `items.view`; generating a barcode needs `items.edit`; every generation is in the audit log.
